<h1>Assistant</h1>
<p class="sub">A bounded agent around a deterministic legal core.</p>
<nav class="dossier-tabs" aria-label="Architecture dossier"><a href="/built">Overview</a><a href="/built/model">Legal model</a><a href="/built/data">Data authority</a><a href="/built/retrieval">Retrieval</a><a href="/built/assistant" aria-current="page">Assistant</a><a href="/built/release">Release</a><a href="/built/decisions">Trade-offs</a><a href="/built/incidents">Incidents</a><a href="/built/limits">Limits and scale</a><a class="dossier-print" href="/architecture/dossier">Complete dossier</a></nav><article class="architecture-dossier"><p><strong>Architectural decision: bounded plan -&gt; validate and correct once -&gt; freeze -&gt; execute.</strong> This is
ReWOO-inspired reasoning without an observation loop, not adaptive ReAct. Retrieval constrains what the
model can know, so exact identity and time resolution happen before planning; the planner proposes a
typed operation plan, while application code authorizes, executes and returns the normal cited result.</p>

<p>The canonical <code>LegalOperationCatalog</code> is the shared contract. The planner receives its closed typed
schemas but never calls MCP, SQL, vectors or the index. After validation and freeze, the executor
calls the deterministic legal core. Public MCP projects the same operations independently for
external clients; it is not the assistant's internal transport.</p>

<td>Direct usable answer, <code>NeedsClarification</code>, gap or refusal without generated prose</td>
</tr>
<tr>
<td>Optional compose and judge</td>
<td>Explicit prose request may activate two separate logical Agent Framework roles</td>
<td>Composer draft; judge only factual Answer or Gap claims; fallback keeps the deterministic result</td>
</tr>

</table></div>
<h2>Why this design</h2>
<div class="dossier-table" tabindex="0" role="region" aria-label="Scrollable architecture table"><table>
<thead>
<tr>
<th>Approach</th>
<th>Decision</th>
<th>Product consequence</th>
</tr>
</thead>
<tbody>
<tr>
<td>Bounded plan, freeze and execute</td>
<td>Chosen</td>
<td>Identity and time resolve first; typed and cited outcomes stay useful even without generated prose.</td>
</tr>
<tr>
<td>Open-ended ReAct</td>
<td>Rejected</td>
<td>Observing refusals and replanning can drift to another law while adding unbounded latency and model cost.</td>
</tr>
<tr>
<td>Naive RAG with LLM-selected identity</td>
<td>Rejected</td>
<td>Ambiguous retrieval can silently choose the wrong instrument and turn missing evidence into unsupported claims.</td>
</tr>
</tbody>
</table></div>
<p>The catalog, plan schema, executor, outcomes and evidence contracts are explicit application code;
no LangChain or LlamaIndex loop hides chunking, tool selection or retry behavior. The planner cannot
observe tool results and replan. The judge verifies only optional generated factual prose;
deterministic typed results need no LLM judge.</p>
<h2>Control flow</h2>
<ol>
<li>The web boundary validates the bounded request, idempotency key and evaluation admission when
present, then acquires one server thread lease. Admission applies request ownership,
concurrency, daily cost and first-result deadline limits.</li>
<li>The thread registry restores at most six accepted turns and deterministic subject context from
a SHA-256 token digest. The browser presents the opaque token but owns no durable memory.</li>
<li>Subject preflight queries the signed work catalog before the planning model is called. Exact
identifiers and exact publisher-provided short titles may authorize a work. Weaker official
classifications remain discovery evidence only. Ambiguity is kept as clarification context,
never converted into a silently selected law.</li>
<li>The bounded planning agent receives the question, bounded history, closed operation schemas and
only opaque <code>subject_ref</code> values authorized by preflight. Without authority, work-specific
operations receive no subject reference.</li>
<li>The canonical plan gate validates operation names and typed arguments. One bounded corrective
turn is allowed for a contract-shape error; a second invalid plan becomes a typed invalid request.</li>
<li>The plan is frozen at no more than eight operations. There is no model observation or replanning
after this point.</li>
<li>The shared legal core executes each operation against the signed index and returns a closed
outcome, rows, hashes and publisher links. <code>NeedsClarification</code>, legal-boundary and transport
gaps stay typed rather than being rewritten as apparent answers.</li>
<li>The outcome router builds the normal answer, result cards and citations deterministically. Its
evidence ledger is bounded to 64 entries and 96,000 characters.</li>
<li>The planner may set <code>synthesis=true</code> only when the reader explicitly asks to explain, describe
or summarise the accepted results. There is no hidden UI toggle. For example: &quot;Show Article 6
on 1 Jan 2021 and explain it.&quot;</li>
<li>Runtime additionally requires no displayed clarification, no <code>NeedsClarification</code> result, no
transport failure, and at least one accepted operation that is not an inventory. <code>coverage</code>,
<code>cited_by</code> and <code>in_force_on</code> return closed typed lists the deterministic reply already renders
in full and carry no publisher text to describe, so the same coverage question once served 294
output tokens and once 4,973 with a composer; the flag is now reconciled against the frozen
plan rather than trusted, and never against the reader's words, which quoted content controls.
The grounded composer and conditional judge are two separate logical
Microsoft Agent Framework agents with separate sessions over the same configured Azure OpenAI
chat client and deployment used by Ask. They are roles, not a second deployment or an
autonomous observation loop.</li>
<li>The composer receives the deterministic draft plus typed evidence and gets at most one format
or evidence-contract correction. The judge runs only for Answer or Gap drafts with factual
claims, then returns Pass, Repair or Refuse. A synthesis deadline or outage preserves the
deterministic verified result.</li>
</ol>

<h2>Conversation memory</h2>
<p><img src="/built/diagrams/memory.svg" alt="The browser keeps only a visible transcript and opaque token while bounded server memory stores six accepted turns and deterministic subject context, expiring after thirty idle minutes." /></p>
<p><a href="/built/diagrams/memory.svg">Open the memory boundary diagram at full size</a></p>
<div class="dossier-table" tabindex="0" role="region" aria-label="Scrollable architecture table"><table>
<thead>
<tr>
<th>Boundary</th>
<th>Responsibility</th>
<th>Implementation</th>
</tr>
</thead>
<tbody>
<tr>
<td>Browser component memory</td>
<td>Keep the visible transcript and opaque capability for this tab only</td>
<td><code>web/src/AssistantController.tsx</code></td>
</tr>
<tr>
<td>Server thread registry</td>
<td>Bound accepted turns, deterministic subject context, waiters, expiry and eviction</td>
<td><code>Lex.Web/AskThreadRegistry</code></td>
</tr>
<tr>
<td>Planner request</td>
<td>Receive only the restored bounded transcript and authorized subject references</td>
<td><code>Lex.Ask</code> operation planning</td>
</tr>
</tbody>
</table></div>
<p>Conversation memory is server-owned and ephemeral: at most 1,024 threads, six accepted turns,
32 KiB per thread, 16 MiB globally, two waiters per thread and a 30-minute idle lifetime. The
browser holds the visible transcript and opaque capability in component memory, not local storage.
Only the token's SHA-256 digest is retained server-side. Restart, expiry, eviction or reset loses
the thread safely; an unknown token never falls through to another conversation.</p>
<p>The public default admits 200 accepted turns per ingress-derived client address and 400 globally
per UTC day. Those process-local controls are honest cost and abuse limits, not user identity.</p>
