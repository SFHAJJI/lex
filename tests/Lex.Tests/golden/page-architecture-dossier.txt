<article class="architecture-dossier architecture-dossier-full"><h2>Overview</h2>
<p>Lex answers a narrow business question: <strong>what did this rule say on this date?</strong> It turns dated

version and a verifiable evidence chain. It does not decide legal applicability or advise a reader

<h3>The architecture in one sentence</h3>
<p>Official publisher records become immutable evidence, deterministic derivations and signed local
indexes; one typed legal core serves the UI, MCP and a bounded agent whose model may plan and
explain but cannot choose legal identity, dates, evidence or actions.</p>
<h3>How to read this dossier</h3>
<p>The first four tabs explain the legal and retrieval product. <strong>Assistant</strong> shows where the agent is
useful and where it has no authority. <strong>Release</strong> shows how evaluated code and data become one
rollback-safe revision. The final three tabs expose decisions, incidents and limits instead of
hiding them behind a feature list.</p>
<p>The pages describe durable contracts, not a moment in one rollout. Mounted corpus identities,
coverage and retrieval capabilities are read from the running revision, while latency, relevance,
memory and promotion claims appear only when a signed report binds them to that exact artifact set.</p>
<h3>Why this is more than a naive RAG</h3>
<p>Lex is retrieval-augmented generation only when the reader asks for prose. Identity resolution,
point-in-time selection, retrieval, comparison, citations and direct result cards work without
generation. The default result is deterministic. Optional prose receives an already bounded
evidence ledger and must bind each claim back to that ledger.</p>
<h2>Legal model</h2>
<p>The core modeling choice is to keep a law, a dated legal state, a language expression and the
publisher file as different things. Collapsing them into one document would make a date lookup
ambiguous and make provenance impossible to state precisely.</p>

<h3>Empty is a modeled outcome</h3>
<p>A publisher can announce a state before supplying exploitable wording, or provide a manifestation
that the current deterministic profile cannot safely segment. Lex keeps that state and returns a
typed availability reason with the official link. It does not synthesize a consolidation or copy
text from another date. In this product, an honest gap is useful data.</p>
<h3>What stays outside the model</h3>
<p>Human-authored aliases, model-inferred classifications and generated legal text do not become
corpus authority. Official short titles may identify a work only when the source literal is an
exact unique match. Official taxonomies remain discovery metadata and never prove historical
applicability or legal wording.</p>

<h3>Official discovery metadata</h3>
<p>Luxembourg acquisition mirrors Legilux <code>subjectLevel1</code> and <code>subjectLevel2</code> assertions with the

their identifiers and source URIs. The two vocabulary systems remain distinct.</p>

not contain the query phrase and the result can say which official classification matched. They do
not establish legal identity, support a legal claim or become historical evidence. No manual legal
alias catalogue and no model-generated metadata enter production authority.</p>

<h3>Retrieval funnel</h3>
<ol>
<li>Parse explicit dates, identifiers, article numbers and comparison intent.</li>
<li>Resolve the named subject against official work identity before asking the planner.</li>
<li>Clarify zero or several credible subjects instead of letting rank silently choose one.</li>
<li>Apply publisher, work, language and point-in-time scope.</li>

<h3>Why keyword remains the default</h3>
<p>The semantic encoder, local vectors and rank fusion exist, but activation is evidence-gated. The
frozen 200-case catalog fixes tuning and holdout judgments before measurement. A compatible signed
report must bind relevance, latency, memory and size to the exact candidate before hybrid may become
the default; without that evidence, keyword remains the default. A measured rejection is a valid
architecture result, not a failed demo.</p>
<h2>Assistant</h2>
<p><strong>Architectural decision: bounded plan -&gt; validate and correct once -&gt; freeze -&gt; execute.</strong> This is
ReWOO-inspired reasoning without an observation loop, not adaptive ReAct. Retrieval constrains what the
model can know, so exact identity and time resolution happen before planning; the planner proposes a
typed operation plan, while application code authorizes, executes and returns the normal cited result.</p>

<h3>Control flow</h3>
<ol>
<li>The web boundary validates the bounded request, idempotency key and evaluation admission when
present, then acquires one server thread lease. Admission applies request ownership,
concurrency, daily cost and first-result deadline limits.</li>
<li>The thread registry restores at most six accepted turns and deterministic subject context from
a SHA-256 token digest. The browser presents the opaque token but owns no durable memory.</li>
<li>Subject preflight queries the signed work catalog before the planning model is called. Exact
identifiers and exact publisher-provided short titles may authorize a work. Weaker official
classifications remain discovery evidence only. Ambiguity is kept as clarification context,
never converted into a silently selected law.</li>
<li>The bounded planning agent receives the question, bounded history, closed operation schemas and
only opaque <code>subject_ref</code> values authorized by preflight. Without authority, work-specific
operations receive no subject reference.</li>
<li>The canonical plan gate validates operation names and typed arguments. One bounded corrective
turn is allowed for a contract-shape error; a second invalid plan becomes a typed invalid request.</li>
<li>The plan is frozen at no more than eight operations. There is no model observation or replanning
after this point.</li>
<li>The shared legal core executes each operation against the signed index and returns a closed
outcome, rows, hashes and publisher links. <code>NeedsClarification</code>, legal-boundary and transport
gaps stay typed rather than being rewritten as apparent answers.</li>
<li>The outcome router builds the normal answer, result cards and citations deterministically. Its
evidence ledger is bounded to 64 entries and 96,000 characters.</li>
<li>The planner may set <code>synthesis=true</code> only when the reader explicitly asks to explain, describe
or summarise the accepted results. There is no hidden UI toggle. For example: &quot;Show Article 6
on 1 Jan 2021 and explain it.&quot;</li>
<li>Runtime additionally requires no displayed clarification, no <code>NeedsClarification</code> result and no
transport failure. The grounded composer and conditional judge are two separate logical
Microsoft Agent Framework agents with separate sessions over the same configured Azure OpenAI
chat client and deployment used by Ask. They are roles, not a second deployment or an
autonomous observation loop.</li>
<li>The composer receives the deterministic draft plus typed evidence and gets at most one format
or evidence-contract correction. The judge runs only for Answer or Gap drafts with factual
claims, then returns Pass, Repair or Refuse. A synthesis deadline or outage preserves the
deterministic verified result.</li>
</ol>

per UTC day. Those process-local controls are honest cost and abuse limits, not user identity.</p>

<p><code>maxInactiveRevisions</code> is one in steady state and two only while a candidate waits. Azure Container
Apps has no supported per-revision delete. An unresolved newer candidate cannot be discarded by
lowering the limit without risking the older valid rollback, so cleanup follows identity and
creation order rather than age.</p>
<h3>Evidence before traffic</h3>
<p>The deploy workflow builds an immutable image from the exact code commit and signed artifact set,
creates a zero-traffic revision, and checks readiness, MCP, Luxembourg and EU search. The assistant
evaluation binds frozen cases, exact candidate, tool outcomes, injection canaries, latency and cost
to a signed report. Human review uses a separate signing authority. Only the traffic workflow can
verify those records and promote. No automated actor can approve its own release.</p>
<p>Release state is never hard-coded into this page. The mounted-evidence section below reads the
running revision's identities and indexes; candidate evaluation and promotion remain authoritative
only through their matching signed reports and receipts.</p>
<p>Scale is a release invariant, not a stale observation: the traffic workflow accepts a target and
rollback only when each is pinned at <code>min=max=1</code>. Quotas, idempotency and thread state must be
externalized before a multi-replica release is allowed.</p>
<h3>Container registry and Blob retention</h3>
<p>The Azure Container Registry is shared and still has a legacy RBAC boundary. Broad digest deletion
is rejected because Lex's revision inventory cannot prove that another application does not pull a
digest. The clean target is either a dedicated Lex registry or an audited migration of every shared
consumer to repository-scoped ABAC roles and managed identities. Only then may an exact digest
allowlist become an automated deletion plan.</p>
<p>Private prebuilt staging blobs have a narrower ownership proof. The publisher may delete only the
exact staging paths it created, with matching ETags, after both the immutable Blob release and the
public release have been downloaded and hash-verified. Release paths are never cleanup candidates.</p>

<h3>Three decisions to challenge</h3>
<p><strong>Why no ReAct loop?</strong> The measured dangerous failures were identity and evidence failures. Letting a
model observe a deterministic refusal and try a different law can convert an honest gap into a
plausible answer. One correction before execution fixes contract syntax without changing authority.</p>
<p><strong>Why build semantic retrieval and leave it off?</strong> Because architecture is a reversible hypothesis.
The vectors and encoder prove the path can run; the frozen holdout decides whether it should serve.
The next activation can be category-specific rather than a global switch.</p>
<p><strong>Why not unify taxonomies?</strong> EuroVoc and Legilux classifications have different authorities,
languages and semantics. Preserving the source scheme makes a match explainable. A unified label
would be a new assertion owned by Lex and would need its own governance and evaluation.</p>
<p>Status vocabulary records implementation maturity, not current traffic: <code>shipped</code> means included in
the release line, <code>gated</code> means activation still depends on evidence, and <code>planned</code> means no product
claim yet. Mounted identities and signed promotion receipts separately establish what a running
revision serves.</p>

<h3>The retrieval lesson</h3>
<p>The CRR/EMIR case adds a failure class to the usual RAG discussion: <strong>right passage, wrong
instrument</strong>. A groundedness judge cannot detect it because the generated sentence is faithful to
the evidence it received. The control must sit earlier, at subject identity, and the answer must
name the selected instrument so a reader can see the decision.</p>
<h3>Incident template</h3>
<p>Every new entry records symptom, business effect, detection, why it survived, root cause, fix,
guard, deliberate-break proof and residual risk. That format prevents a postmortem from becoming a
timeline without an architectural consequence.</p>

<h3>Known limitations that matter to a reader</h3>
<ul>
<li>Some official states contain no safely extractable wording; they remain explicit gaps.</li>
<li>Provision extraction quality has a historical empty-text backlog. The additive Memorial v2
profile is shipped in code, while the refreshed corpus measurement waits for the v4 ingestion.</li>
<li>EU citation edges and amendment relations are not yet a complete query surface.</li>
<li>MCP comparison identifies changed states but does not yet return every provision-level text diff.</li>
<li>Production diagnostics are sanitized but not all are correlated end to end by request id.</li>
<li>Shared ACR cleanup remains inventory-only until registry ownership is isolated or audited.</li>
</ul>
<p>The detailed and dated backlog lives in <a href="https://github.com/SFHAJJI/lex/blob/main/docs/known-defects.md">known defects on GitHub</a>.
Deliberately absent: generated consolidation, model-derived legal identity, silent taxonomy merging,
unbounded replanning and a framework rewrite.</p>
<h2 id="delivery-registry">Delivery registry</h2>
<p>The target path is reviewed EU scope, official dated expressions, content-addressed
text states, FTS5 keyword candidates plus local compact semantic candidates, temporal and
hierarchy eligibility, fixed rank fusion, and the same typed result contracts. A capability
is not described as live until its registry status and release evidence agree.</p>
