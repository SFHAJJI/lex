# Lex V3 launch contract

The checklist that must hold on the exact tuple promoted to production. Each line names its evidence.
It supersedes the nine stage terminals for launch; Decisions 82 to 93 in lex-governance still bind
product scope. Anything not listed here ships after launch.

## Promises to the reader

- [ ] Every quote carries `text_sha256`, `body_sha256`, the official source URI and a permalink that
      pins work, article, date, language and digest. Evidence: `verify` resolves every citation the
      product emitted in the journey suite.
- [ ] A dated request never receives a different date silently: `as_of` and `in_force_on` refuse
      `ambiguous_version` or `no_version_for_date` rather than choose. Evidence: temporal case set at
      100 percent.
- [ ] Every absence is typed: the closed registry of 20 refusal codes with mandatory payloads is the
      only way to say no. Evidence: refusal case set at 100 percent; registry digest in every envelope.
- [ ] Image-only annexes stay `text_not_available`, officially linked, out of search, quotes and
      exports. Evidence: the annex control case.
- [ ] Rights are enforced at compose time; derived, unofficial and non-redistributable bodies never
      enter an evidence bundle as authoritative text. Evidence: bundle composer type test plus one
      licence-blocked journey.
- [ ] Luxembourg applicability dates and EU wording-state dates are never merged, in text or in speech.
      Evidence: timeline speech test per publisher.
- [ ] No model retrieves, reranks or authors authoritative text. `ask` answers
      `assistant_v3_unavailable`. Evidence: registry and host census.
- [ ] Derivation and indexes are byte-stable across two independent executions. Evidence: two-build
      digest comparison in the release pipeline.

## Surface at launch

- [ ] Operations served for Luxembourg and EU from the mounted corpus: all 27 registered names, each
      either served or refusing with a typed reason its capability manifest states.
- [ ] REST and MCP (streamable HTTP) derive identical envelopes from the registry.
- [ ] Events: append-only log, cursor polling at-least-once, `answer_drift`. No webhooks (Decision 93).
- [ ] Screens: Search, Work dossier, Reading with the as-of control, Provision history, Compare,
      Radar, Trust and Coverage, Export composer. Journeys J1 to J8 pass in a real browser.
- [ ] Exports PDF, JSON, CSV preserve citations, rights, watermarks and exclusions.
- [ ] Chrome in FR and EN; DE and LB answer `localization_unavailable`. Statute language marked
      independently of chrome language in markup.
- [ ] Accessibility: no meaning by colour alone, linear diff, explicit dates, bracket tables whole,
      keyboard and screen-reader paths for the eight screens.
- [ ] Security headers on the real host; no query text, IP or user agent recorded.

## Data at launch

- [ ] Complete EU population, English and French expressions (Decisions 84 and 89), every discovered
      body with one typed outcome.
- [ ] The Luxembourg population as authorised by the owner, every discovered body with one typed
      outcome.
- [ ] Robots evaluated literally per requested URL (Decision 83); one legal-notice GET at Stage 7
      (Decision 88); transport bytes retained before decode.

## Release path

- [ ] One command builds corpus, indexes and manifests from custody, builds and signs the image,
      publishes versioned assets, reads them back and verifies hashes and signatures.
- [ ] Zero-traffic deploy with health, API, browser, privacy and security probes; removal verified.
- [ ] Promotion, a second revision, rollback and forward again, V2 retired and unreachable.
- [ ] Owner sign-off on release lineage and on promotion. Second sign-off by Codex where available.

## Evaluation at launch

- [ ] Machine gates: temporal set 100 percent, refusal set 100 percent, three shuffled controls shown
      to fail, replay G1 to G5, V2 absent from the image.
- [ ] Evaluation card published with the statistical rows marked "not yet labelled". Human-labelled
      datasets and their kappa, holdout and permutation gates follow after launch (Decision 92).
